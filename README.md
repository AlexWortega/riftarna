# Riftbound — Арена стихий

Браузерный прототип магической арены 8×8 в духе Magicka: одиночный бой с 15
ботами или сетевой бой 2–8 людей с ботами в остальных слотах. Игроки
входят в комнату из списка или по ссылке. Графика и модели созданы процедурно; оригинальные
ресурсы Magicka 2 не распространяются.

Демо: https://riftarna-production.up.railway.app

Отдельный [Roblox-прототип от первого лица](roblox/README.md) с деревней,
огнём, молнией и разрушаемыми объектами находится в `roblox/`.

## Запуск

Нужен Node.js 20 или новее. Three.js включён в проект; сервер использует `ws`.

```bash
git clone https://github.com/AlexWortega/riftarna.git
cd riftarna
npm ci
npm start
```

Откройте http://localhost:8080. Сервер принимает HTTP и WebSocket на одном
порту (`PORT` задаётся окружением). Проверка состояния: `/health`.

## Сетевая игра

1. Откройте страницу. Введите ник из 2–18 букв, цифр, `_` или `-`.
2. Создайте комнату и отправьте ссылку друзьям либо выберите открытую комнату
   из списка. По ссылке можно войти до начала боя.
3. Когда соберутся 2–8 игроков, создатель нажимает «Начать бой». Люди
   распределяются между двумя командами; свободные слоты занимают боты.

Бой рассчитывает браузер создателя, сервер передаёт команды остальных игроков
и рассылает состояние всем участникам. При выходе гостя его маг переходит боту;
при выходе создателя матч завершается. Комнаты и ники хранятся в памяти процесса.
Нужен **один экземпляр сервера**: несколько реплик не разделяют список комнат.
Восстановления матча после перезапуска пока нет.

## Что работает

- 3D-карта с тремя линиями, мостами, лесом, укреплениями и ядрами баз.
- До восьми управляемых магов, остальные слоты занимают боты.
- Восемь стихий, очередь до пяти элементов и разные способы применения.
- Лучи, снаряды, молнии, потоки, барьеры, лечение и защита.
- Ускоренное движение и касты, рывок с откатом 2,2 секунды.
- Цветные следы заклинаний на земле, ожоги и искры; огонь зажигает деревья,
  распространяется по лесу и оставляет обгоревшие пни. Вода гасит пожар.
- Воксельные руины: удар выбивает блоки, лишённые опоры части осыпаются;
  обломки отскакивают от земли. Число частиц и следов ограничено.
- Компоненты повреждений, намокание, горение, охлаждение и заморозка.
- Захват святилищ, разрушение укреплений, смерть и возрождение.
- Мини-карта, помощь, масштабирование и сенсорное управление. Пауза доступна
  в одиночной игре.

## Управление на компьютере

| Действие | Управление |
| --- | --- |
| Движение | ЛКМ по карте |
| Вода, жизнь, щит, холод | Q, W, E, R |
| Молния, аркана, земля, огонь | A, S, D, F |
| Направленный каст | ПКМ; удержание для повторного применения |
| Вокруг себя | Shift + ПКМ |

| Быстрый щит | Пробел |
| Рывок к курсору | Shift + Space или Shift + ЛКМ |
| Убрать последний элемент | Backspace |
| Пауза | Esc |
| Масштаб | Колесо мыши |

## Управление на телефоне

- Левый джойстик — движение относительно экрана, отпускание останавливает мага.
- Правый джойстик — направление и каст при удержании; касание — один каст.
- Кнопки стихий — сборка комбинации, в том числе во время движения.
- «На себя» и «Вокруг» — применение комбинации; можно удерживать.
- «Щит» — быстрая защита; «+» и «−» — масштаб камеры.
- «Рывок» — быстрое перемещение вперёд или по направлению правого джойстика.

Сенсорная раскладка включается автоматически, поддерживает обе ориентации
и независимые касания. При паузе, потере фокуса и повороте ввод сбрасывается.
Проверено в мобильной эмуляции Chromium с событиями мультитача.
Производительность на физических iOS/Android устройствах ещё не измерена.

## Тесты

Нужен Node.js 20 или новее. Внешние зависимости не нужны.

```bash
npm test
```

Пятнадцать тестов проверяют состояния, компоненты урона, защиту, здоровье,
мёртвую зону джойстика, преобразование направления и сетевой протокол:
уникальность ников, комнаты до восьми игроков, обмен командами и состоянием, отключение.
Отдельные тесты проверяют выбивание вокселей, падение ячеек без опоры и
применение сетевой маски разрушений.

## Ограничения и дальнейшая работа

Это прототип графики и механик. Сетевой бой зависит от клиента создателя
комнаты, который рассчитывает симуляцию; для соревновательной игры бой
нужно перенести на выделенный сервер.
Разрушаемость адаптирована для WebGL и небольших объектов; это не GPU
симуляция десятков тысяч вокселей. Идея локальных ударов и потери опоры
вдохновлена [three-voxel-destruction](https://github.com/sbobyn/three-voxel-destruction)
(MIT). Код и ассеты примера в проект не копировались.
Коэффициенты урона и приоритеты комбинаций предварительные: точные формулы
Magicka 2 ещё не извлечены и не перенесены. Осадные големы, волны NPC,
рейтинг и подбор игроков пока не реализованы.

Ориентир для переноса: [RunFMe/magicka2-native-port](https://github.com/RunFMe/magicka2-native-port).
Полезные точки наблюдения: `SpellCastingSystem`, `HealthSystem`,
`EntityAux.add_damage` в `work/engine-port/integration/spell-matrix/spell_matrix_probe.lua`
и `work/engine-port/engine/physics/tests/probes/damage_probe.lua`.

Для точного переноса нужны оригинальные Lua-скрипты из локальной
Steam-установки игры. Далее: зафиксировать поведение оригинала проверками,
заменить предварительные правила и отдельно настраивать PvP-баланс.
